1.3.6 is released! Mostly TheInsanityGod's reports, and what turned up chasing them:

### For mod authors

*   A field inside a dictionary or list entry gets the same control its attributes earn at the root — a slider for a [Range], a dropdown for an enum, an empty box for a nullable — and the same validation, with the container's row naming the entry and field that failed
*   A dictionary keyed by an enum offers its members rather than a text box; a [Flags] key accepts a combination; a numeric key is checked against its own type, so 300 is refused for a byte and a ulong past long.MaxValue is not
*   Enums backed by a byte, short or long register — they threw at registration before, and the mod did not load
*   A field added to a class after files were written reads as the class's own default in every stored entry, on screen and in validation, rather than as null

### For players

*   A refused value marks its own row: the label turns red and a mark appears past Reset with the message as its tooltip, so you no longer have to look at the foot of the window to find it
*   A nullable number stays empty when you click away from it, instead of turning into 0

### Fixes

*   The lag spike with "Texture ... is leaking memory" in the log: rows scrolled out of view on a long list were never freed when the screen rebuilt after a remove, add, rename or fold
*   A saved enum choice was reset to its default on every start — and written back over the file; it loads now, by name or by number
*   Choosing "(unset)" on a nullable enum kept writing the old member
*   An enum inside an entry that the file stored as a number showed the first member instead of the right one
*   A null entry in a dictionary no longer fails validation as an object with every field null
*   A mistyped enum or numeric key is refused with a message instead of being written to the file and lost on the next load
*   The colour swatch beside a colour field now redraws as you type, and no longer leaks

Thanks to [TheInsanityGod](https://mods.vintagestory.at/show/user/B5486CC4FCE8B1143B89) for the reports, and for the traced log that pinned the leak down to a line.
