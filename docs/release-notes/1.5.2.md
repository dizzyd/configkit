1.5.2 is released! "AutoConfigs": true no longer breaks mods that adjust their config after loading it, found through Toolsmith.

For players

* With "AutoConfigs": true, Toolsmith stopped working after a launch or two: it was still installed, but tools behaved as if it were off. ConfigKit put the previous launch's tool lists back in the middle of Toolsmith rebuilding them, so each launch added another copy until they matched no tool. Toolsmith now works with AutoConfigs on, and a Toolsmith.json the bug already damaged repairs itself on the next launch.

For mod authors

* When AutoConfigs takes over a config, the object your mod loaded is now the source of truth. The settings screen starts from what that object holds, including anything your mod changed after loading, and ConfigKit no longer writes the file's values over it. Edits from the screen and values from the server still reach it as before.
* A value your own validation attributes reject, such as [Range], is still flagged on its row.
