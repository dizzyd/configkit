1.4.2 is released! A closed world is let go of instead of staying in memory.

For players

* Every world you left kept its whole server in memory until the game was closed, so leaving one singleplayer world and opening another grew the game's memory each time. A closed world is freed now.

For mod authors

* The static ConfigKitModSystem.ConfigsChanged event is cleared when the world closes. A handler subscribed there kept your mod system, and the world behind it, alive into the next world and was called again there. Subscribe in each world's start-up, as you would any other event.
* Running more than one server in one process, as a test harness does, no longer keeps every one of them. One headless suite grew by about 2 GB a server before this.

Thanks to Benjamin Kirkbride (https://github.com/benjamin-kirkbride) for finding the leak, measuring it, and sending the fix.
